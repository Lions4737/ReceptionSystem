# UTPoker Komaba Festival MVP

学園祭ポーカー受付。Next.js App Router の画面・Route Handlersを、SitesのvinextランタイムでCloudflare Workers向けにビルドします。保存先はD1です。標準の `next build` / OpenNext構成ではありません。

## ローカル起動

Node.js 22.13以降を推奨します。

```sh
npm ci
npm run setup:local
npm run dev
```

http://localhost:3000 で来場者画面、 `/staff/login` で運営画面を開きます。ローカル管理者キーは `work/mvp-access.txt` にあります。キーはGit対象外です。`.dev.vars`作成後に開発サーバーを起動してください。

## 操作

1. 来場者は `/join` から匿名受付し `/me` で番号・待ち状況を確認します。
2. 責任者または受付は `/staff/reception` で呼び出し、入金登録、席の割り振り・着席案内を行います。
3. ディーラーは `/staff/table` でテーブルを選び、説明後に個人の時間を開始します。
4. 時間到達後、最終点数を入力して終了すると席が空きます。0点も入力できます。
5. `/staff/settings` からイベント名・テーブル構成・料金・時間・初期チップを変更できます。責任者は受付一覧の対象行で点数訂正ができます。開始前の返金・取消は対象行の編集画面から行えます。
6. `/display` はスタッフログイン済みの端末で開く会場モニターです。

運営メンバーは `/staff/login` で共有パスワードを入力します。ローカルでは `.dev.vars` の `STAFF_PASSWORD`、本番では Worker シークレットの `STAFF_PASSWORD` に設定します。変更には実行環境の設定権限が必要です。責任者は同じ画面で、自分だけが保管する `SETUP_KEY` を入力します。来場者には `/join` を案内してください。

テーブル・席数設定では、名前・対象タグ・席数のセルから直接変更できます。名前と席数はEnterまたはフォーカスを外すと保存し、Escapeで編集を取り消します。対象タグと「割り振りロック」は選択時に保存します。ロックした卓には新しい人を割り振れませんが、すでに確保・着席・プレイ中の席は維持し、そのまま進行できます。

各卓の「卓を空にする」から、同じ対象タグの他の卓への移動先を確認し、全員を一括で移動できます。移動先はロック・削除されていない卓の空席から、利用人数が少ない卓を優先します。全員分の空席がない場合や確認中に席・卓が変わった場合は移動しません。元の卓は割り振りロックになり、空席の状態を維持します。受付番号・入金・ステータス・プレイ時間を引き継ぎ、一時停止していた卓からの移動では停止時間を残り時間に反映します。移動後も一覧で案内先を確認でき、移動前後の記録は操作履歴に残ります。

受付一覧の「呼び出す」は受付番号を表示するだけで、席は確保しません。現金を受け取って「入金」を登録した後、「席を割り振る」から着席案内を行います。この段階で「自動で割り振る」が初期選択され、確定時に同じ対象タグの卓のうち、席を確保済みの人数が最も少ない卓を優先します。呼び出し中でも席の未割り振りの人は、その卓の人数に含めません。同人数の卓が複数あれば各卓を同確率で抽選し、その卓の空席をもう一度同確率で抽選して確保します。卓と席を別々に抽選するので、席数の多い卓が抽選で有利になることはありません。ロック中・一時停止中・満席・削除済みの卓は除外します。定員の割合ではなく人数を揃え、同じ定員の空の卓から新規案内を続ける場合は人数差を1人以内に保ちます。途中退出などによる差は、以後の案内で少人数の卓を優先して縮めます。入金後の席の手動指定も可能です。未入金では通常操作・手動ステータス修正のどちらでも席を割り当てられません。入金後に空席がなくなっても、入金済み・席未割り振りのまま案内を待てます。再度割り振る際の二重入金はなく、案内前の返金・取消も可能です。空席ができた時やロック解除時に、待機者を自動で呼び出したり割り振ったりすることはありません。席の選択と確保は一括処理し、同時操作による重複割り振りを防ぎ、操作履歴に残します。 同じ操作の再送では抽選をやり直さず、確保済みの席を維持します。

この方式は [Poker TDA 2026規則](https://www.pokertda.com/view-poker-tda-rules/)のランダムな席割りと人数調整の考え方を、時間制の体験受付に合わせた運用です。大会の卓間移動には次のビッグブラインドなどの位置を考慮する規則があるため、通常の自動割り振りは新規案内時に適用します。「卓を空にする」は運営が指定したときだけ実行し、ブラインド位置の管理は行いません。

受付一覧は列幅を固定し、長いニックネームは省略表示します。名前にカーソルを重ねると全文を確認できます。「操作」列の鉛筆アイコンから、変更後のステータス・必要な席・終了点数を指定できます。責任者・運営スタッフ・受付スタッフが、プレイ中・終了を含む状態を変更できます。タイマーのリセット・点数消去・席の解放などの影響がある場合は、警告を確認してチェックを入れてから保存します。待機・呼出・保留・取消への変更は未入金、開始待ち・プレイ中・終了への変更は入金済みに修正し、差額を会計記録に追記します。同じステータスの編集では入金状態を保持します。現金の受け渡しも警告で確認します。返金済みの受付は再利用できません。プレイ中への変更はその時点から所定の時間を開始し、不在・保留から待機への変更は同じ対象の待機列の先頭へ戻し、それ以外の状態から待機への変更は末尾へ戻します。変更前後の状態は操作履歴に残ります。

スタッフ用と来場者用のセッションは分かれています。同じブラウザでスタッフログインを維持したまま `/join` から通常受付し、`/me` で自分の番号を確認できます。スタッフのログアウト後も来場者の受付は残ります。通常受付は待機列へ実際に登録されます。

来場者画面には運営画面へのリンクを表示しません。スタッフは `/staff/login` からログインします。受付中の `/me` には「ブラウザを閉じないでください」「受付が完了するまで、この画面を開いたままにしてください。」と表示し、受付情報の保存欄は表示しません。同じブラウザならホームの「自分の受付」から戻れます。受付一覧には「受付リンク」ボタンを表示しません。既に取得した専用リンクと復帰コードによる復元も引き続き利用できます。復元しても受付番号・待機順・入金状況は変わりません。

受付中の `/me` では、対応ブラウザでページを閉じる・再読み込み・ページ外へ移動する際に標準の確認を表示します。終了・取消後は解除します。ページ内での操作が必要で、確認文はブラウザ固定です。スマホのタブ削除やアプリ強制終了などでは表示されない場合があるため、画面上にもブラウザを閉じないよう案内を表示します。サイト内の画面切り替えは確認の対象外です。

テーブル管理は [Multi-Timer](https://github.com/Lions4737/Multi-Timer)（参照コミット `a674d7853895dbc2b1a4e399e6791c2c1518db8b`）のカード配置と大きな時・分・秒の表示を参考にしています。設定した席数を画面幅に合わせて3列・2列・1列で表示し、上部から卓全体を一括停止・再開、各席から開始・点数確定ができます。時間切れは赤で強調します。受付・座席・時刻は既存のサーバーと同期し、個別停止・時間変更・リセットは追加していません。

## MVPの運用前提

- 個人30分。説明後にディーラーが開始。500円・初期1000ptは暫定設定。
- 初期構成は0卓・0席です。運営設定の「テーブルを追加」から、名前（30文字以内）・対象（初心者／経験者）・席数（1〜9席）を選んで作成します。卓の追加・削除と構成の変更ができ、A・B・Cの固定卓はありません。
- 席を確保済みの人がいる卓は削除・対象変更できません。席数は使用中の席番号を下回れません。削除しても過去の受付・会計・点数記録は保持します。削除済みの卓は運営設定に表示しません。
- 卓名・席数・空席数・待ち時間・招待の担当卓は保存した構成に連動します。対象の卓が0卓なら、その対象の新規受付はできません。固定の会場名・教室名は表示しません。
- 個人の離席では停止せず、卓全体の停止時間は終了時刻に加算。
- 「1人の時間」を保存すると、受付済み（待機・呼出・開始待ち・不在）とプレイ中にも適用します。プレイ中は開始時刻と停止時間を保ち、各受付の旧時間との差だけ終了予定を増減します。短縮後の所定時間を過ぎていれば時間終了表示になります。終了・取消済みと削除済み卓の記録、入金・初期チップは変更しません。
- 0秒になっても自動で席は解放しません。最終ハンドの扱いは運営で統一してください。
- 待ち時間は各席の終了予定と5分の入替を仮定した目安。呼び出しだけでは席を確保せず、席未割り振りの呼出済み人数も待ち時間の目安に含めます。
- 入金記録は現金受け取り後。返金記録は実際の返却を確認後。
- 呼出後3分経過で不在処理。不在からの復帰は同じ対象の待機列の先頭（次の呼び出し位置）へ戻します。受付停止は手動です。
- 公開番号では本人画面に入れません。本人セッションと復帰コードは発行から7日、スタッフは12時間です。専用リンクと復帰コードは本人だけが保管してください。
- 責任者キーは環境変数 `SETUP_KEY` に32文字以上のランダム値で設定します。
- 毎秒の表示は端末内。スタッフ10秒、モニター15秒、本人45秒で取得。非表示時は定期取得を停止。

## 検証

開発サーバーとローカルD1を起動した状態で:

```sh
npm run typecheck
npm test
npm run build
```

手動ステータス変更の検証は `node --test tests/manual-status.test.mjs` で実行できます。検証用のローカルDBを使い、`TEST_URL` でサーバーを指定できます。席・タイマー・点数・会計の整合性、権限、同時更新、返金後の再利用拒否を確認します。

テーブル構成の検証は `node --test tests/table-config.test.mjs` で実行できます。追加・編集・削除・復元、利用中の席の保護、同時操作、動的な担当卓を確認します。全卓を削除するケースは使い捨てのローカルDBに対して `TEST_URL=http://127.0.0.1:3001 TEST_ISOLATED=1 node --test tests/table-config.test.mjs` で実行してください。

割り振りロック・入金後の自動席選択は、使い捨てのローカルDBに対して `TEST_URL=http://127.0.0.1:3001 TEST_ISOLATED=1 node --test --test-concurrency=1 tests/auto-assignment.test.mjs tests/table-config.test.mjs tests/manual-status.test.mjs` で検証できます。呼び出し時の席未確保、未入金の割り振り拒否、二重入金防止、満席時の入金保持、タグ・空席・利用人数による選択、手動割り振りとステータス修正を含むロックの保護、既存利用者の継続、二重実行・席の競合、権限を確認します。

招待コードを使う既存の統合テストは、共有パスワードを設定していないテスト用環境で実行してください。統合テストは匿名本人の分離、権限、重複受付、二重入金、同じ席の競合、個人30分、卓の停止と再開、0点確定、招待の再利用拒否、同一ブラウザでのスタッフ・来場者セッションの共存と旧セッションの引き継ぎ、Cookie消去後の復元、他人の受付の上書き防止、スタッフによる代理受付のリンク発行を確認します。ローカルDBにテストの終了・取消記録が残ります。本番DBへテストを実行しないでください。

## デプロイ

`.openai/hosting.json` の論理D1バインディング `DB` をSitesが構成します。マイグレーションは `drizzle/` にあります。ホスト先の環境変数へ管理者キーを設定し、検証済みのビルドを非公開でテスト公開してください。会場で使うための一般公開・QR配布・端末リハーサルは別途必要です。

Cloudflareの自分のアカウントへ直接公開する場合は、D1を作成し、実DB IDを使う本番Wrangler設定とvinextのWorker出力を接続する追加設定が必要です。`wrangler.local.jsonc` はローカル専用です。

## デザイン

`UTPoker_AI_Design_Guidelines.md` に準拠。白・チャコール・限定的な深い赤、Barlow / Zen Kaku Gothic New / M PLUS 1、細い罫線を使用します。ヘッダーはUTPokerのロゴマーク（`public/utpoker-logo.svg`）と、ひと続きのイベント名を表示します。副題は表示しません。イベント名は責任者が「運営設定 → イベント名」で変更できます（必須・80文字以内）。既存の `settings.event_name` に保存し、受付・運営画面とブラウザのタブ名に反映します。開いている画面は通常の状態更新時または再表示時に反映し、新しく開く画面には最初から保存された名前を表示します。書体は `public/fonts/` に自己ホストし、ライセンスを同梱しています。

共有画像 `public/og.png` は組み込みimagegenで生成。指示文: POKER FESTIVAL / CAMPUS POKER EXPERIENCE / PLAY. CONNECT. ENJOY. を、チャコール #1E1F21、白 #FFFFFF、短い赤 #AA1F24 の罫線、大きなサンセリフ見出しと広い余白で構成。ロゴ・スート・カード・チップ・影・グラデーションを使わない。

卓を空にする操作の検証：使い捨てのローカルDBで `TEST_URL=http://127.0.0.1:3001 TEST_ISOLATED=1 node --test tests/empty-table.test.mjs`。全員の移動、対象タグ・ロック・空席の制約と停止中の卓への移動、残り時間・入金・履歴の保持、権限、再送、同時操作を確認します。

時間設定の検証：使い捨てのローカルDBで `TEST_URL=http://127.0.0.1:3001 TEST_ISOLATED=1 node --test tests/duration-settings.test.mjs`。既存受付への反映、短縮・延長、一時停止・再開、再送、古い状態での開始拒否、終了記録・入金の保持を確認します。

画面間の同期：保存成功時に同一ブラウザのタブへ更新通知を送り、各画面が共有DBから再取得します。取得中の更新要求も破棄せず、取得完了後に再取得します。別端末はスタッフ画面2秒・公開画面5秒ごとの更新で反映し、再表示・フォーカス復帰・オンライン復帰でも同期します。卓設定と受付・座席は一つのDBトランザクションで取得します。結果入力中の座席表示も最新データに追従します。

## 物品販売

運営設定の右側で商品名と単価を登録し、現金の受け取り後に数量を指定して「購入を記録」を押します。商品別の販売数・売上と物販全体の累計を表示します。物販の売上は参加料の集計とは別です。商品登録は「商品を登録」ボタンで開くポップアップから行います。商品別の販売数・売上はイベント集計の下の「物販集計（累計）」に表示します。購入時の単価を保存し、通信再送時の二重計上を防ぎます。責任者・運営スタッフのみ操作でき、商品・購入記録はイベントごとに分離して保存します。

既存環境には `0012_merchandise.sql` の適用が必要です（ローカルは `npm run db:local`）。物販の回帰テストは使い捨てのローカルDBに対して `TEST_URL=http://127.0.0.1:3001 TEST_ISOLATED=1 node --test tests/merchandise.test.mjs` で実行します。

## 経験者卓のリエントリー

プレイ中の経験者卓では、テーブル管理の「リエントリー」から追加料金の受け取りを確認して記録できます。料金は運営設定の「リエントリー料金」でイベントごとに変更できます（初期値300円）。責任者・運営スタッフ・担当ディーラーが操作でき、同じ席・残り時間を維持してチップを200ptに戻します。チップは現物を配り直してください。時間終了後・初心者卓では利用できません。売上に記録時の設定料金を加算し、回数と操作履歴を保存します。再送で二重計上しません。

終了後の「もう一度参加する」は別の通常受付で、前回のニックネームを固定して使用します。APIでも同じ名前を適用します。

使い捨てのローカルDBで `TEST_URL=http://localhost:3001 TEST_ISOLATED=1 node --test tests/reentry.test.mjs` を実行し、経験者限定・料金・時間と席の維持・再送・一時停止・時間終了・名前固定を確認します。

既存環境には `0013_reentry_settings.sql` の適用が必要です。料金の変更前に開いた確認画面からの記録は拒否し、再確認を求めます。
